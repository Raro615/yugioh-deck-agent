### 1.2 확인하지 **못한** 것 (추정도 하지 않는다)

* 공유 URL 의 형식과 리플레이 저장 구조 — **열어 보지 않았다.**
* 자동화로 조작을 재현할 수 있는지(선택자 · 이벤트) — **조사하지 않았다.**
* 토큰이 링크 소재로 쓰일 때의 표현 방식 — 토큰을 놓을 수 있다는 것까지만
  확인했다.

🔴 **이 셋을 추측해서 적지 않는다.** 확인하지 않은 API · URL 매개변수 ·
리플레이 형식을 만들어 내면, 읽는 쪽은 그것이 존재한다고 믿는다.

### 1.3 🔴 이 사이트는 **수동 전개 재현 도구**다

사람이 카드를 끌어다 놓고 그 조작을 기록하는 도구이고, **규칙 판정기가
아니다.** 그러므로 여기서 카드를 배치하거나 재생했다고 해서 실제 게임
규칙의 적법성이 검증된 것이 아니다. 이 저장소의 엔진 실행과 사이트의 재생은
서로를 검증하지 않는다.

## 2. 결론 (6-AR 시점) — **C. 현재 사이트로는 실용적인 자동 연동이 어렵다**

> 🔴 **정정 안내 (Phase 6-AS).** 아래 §2 는 **문서만 읽은 상태**에서 쓴
> 결론이고, 두 군데가 사실보다 넓다.
>
> 1. *"가져오기 경로가 없다"* → **공개 문서에서 확인하지 못했다**가 맞다.
> 2. *"UI 를 자동으로 몰아 리플레이를 만드는 일은 그 금지에 정면으로
>    닿는다"* → 그때 **UI 자동화를 조사하지 않은 상태**였고, 규약은
>    「解析・スクレイピング」과 「과도한 부하」를 금지할 뿐 **일반적인 UI
>    조작 자체를 금지하는 조항을 두지 않았다.** 조항과 작업을 하나씩
>    짝지은 표는 §11.2 에 있다.
>
> 그 뒤 실제로 브라우저에서 조작해 본 결과는 §11.3 이다. 과거 기록은
> 지우지 않고 그대로 둔다.

세 가지가 함께 막는다.

1. **가져오기 경로가 없다.** 盤面은 **덱 이미지에서 잘라낸 카드**로만 만들고
   (§1.1), 카드를 검색해 추가할 수 없다. 우리 기록의 카드 ID 를 넣을 자리가
   사이트에 **존재하지 않는다.**
2. **공개 API 가 없다.** 리플레이를 만드는 유일한 길이 사람의 UI 조작이다.
3. 🔴 **규약이 막는다.** 이용 규약 제3조는
   *"본 서비스의 운영을 방해하는 행위, 과도한 부하를 주는 행위, **해석 ·
   스크레이핑 등의 부정행위**"* 를 금지한다. 리플레이 형식을 역분석하거나
   UI 를 자동으로 몰아 리플레이를 만드는 일은 그 금지에 정면으로 닿는다.
   제4조는 사전 허락 없는 상업적 이용을 금지하고 그 예로 **"법인 서비스에의
   조합(組み込み)"** 을 든다 — 봇이 자동으로 리플레이를 만들어 거는 연동은
   그 조합에 해당할 수 있다.

**B(사람이 일부 준비하면 연동 가능)는 열려 있다, 단 전부 수동이다.** 사람이
직접 ① 덱 이미지를 올리고 ② 아래 §3 의 기록을 보면서 손으로 같은 순서를
재현하고 ③ 기록을 끝내고 공유 URL 을 발행하면, 그 URL 은 다른 사람이 열 수
있다. 🔴 그 과정의 어느 단계도 이 저장소가 자동화하지 않았고, 자동화하려면
**운영자(@miyauchidp)의 사전 허락**이 필요하다.

🔴 **별도의 대형 시뮬레이터를 만들지 않았다.** 대신 §3 · §4 를 했다.

## 3. 한 것 ① — 전개 기록 내보내기 (`engine-replay/1`)

새 모듈 `deck/replay_export.py` 하나다. **실행이 끝난 기록만 읽고** 값 한
장으로 붙인다 (엔진을 다시 돌리지 않는다).

```
format   "engine-replay/1"
source   고정 경로인가 자율 실행인가 · 경로 이름 · 시작 패
result   완료/중단/실행 안 함 · 걸음 수 · 중단 사유 · 경로 진행도
cards    개체 번호 → 패스코드 · 이름 · 주인 · 토큰 여부
initial  시작 판 (좌석 → 존 → 개체 번호)
steps    행동 순서 · 주체 · 수락 · 해결 · 대상 · 소재 · 해결 중 선택 ·
         미지원 · **이 걸음이 만든 사건 번호들**
events   EventJournal 그대로 — action / effect / **cost_payment**,
         카드 이동은 엔진의 delta (`from` → `to`) 를 그대로 싣는다
final    최종 판 · 특수 소환 제한 · 상태 해시
unsupported  이 실행에서 만난 미지원 사유 전부
```

### 3.1 구분해서 적는 것

| 요구 | 어떻게 지켰는가 |
| --- | --- |
| 같은 이름의 카드 여러 장 | 열쇠가 **개체 번호**다. 이름 · 패스코드는 `cards` 표의 값일 뿐이다 |
| 코스트 ≠ 효과 해결 | 사건 종류가 다르다 (`cost_payment` · `effect`). 스켈레촌의 자기 제외는 비용 사건에만 있고 해결 사건에는 없다 |
| 링크 소재 ≠ 대상 | `materials` 와 `targets` 가 다른 칸이다 |
| 토큰 | `token_created` · `token_vanished` 가 제 종류로 남는다. 🔴 **사라진 토큰을 묘지로 보내지 않는다** — 어느 존에도 남지 않는다 |
| 무효 · 불발 · 미지원 | 사건을 만들지 않는다. 그 걸음의 `events` 가 비고, `accepted` · `resolved` · `unsupported` 가 따로 적힌다 |
| 중단 이유 | `result.stopped_kind` · `stopped_reason` · `line_blocked_at` |

### 3.2 🔴 기록만으로 최종 판이 나오는가 — **대조가 있다**

`verify_replay(record)` 가 시작 판에 사건을 순서대로 적용해 최종 판과
맞추고, 어긋나면 어긋난 자리를 문장으로 돌려준다 (**고치지 않는다**).

실측 — 두 경로 모두 **일치**:

| 경로 | 결과 |
| --- | --- |
| `orcust-skeleton-longirsu` | `verify_replay(...) == ()` (일치) |
| `orcust-girsu-token` | `verify_replay(...) == ()` (일치) |

### 3.3 엔진 쪽 최소 보강 두 가지

기존 기록으로는 **시작 판**과 **걸음↔사건 연결**을 알 수 없었다. 그래서
`deck/opening.py` 에 값 두 개만 더했다 (사실을 복사하지 않는다).

* `OpeningRun.initial_board` — 첫 걸음 **전**의 판 한 장.
* `ExecutedStep.journal_from` / `journal_to` — 그 걸음이 늘린 사건 구간.
  둘이 같으면 **판을 바꾸는 사건이 하나도 없었다**는 뜻이다.

### 4.1 변경 전 (6-AQ 후속까지)

같은 입력(`/combo hand:… recipe:… line:orcust-skeleton-longirsu`) 실측:

  검증용 전개 경로 … / 경로: … / 경로가 해결 중에 고르려는 카드: …
  🔴 사람이 적어 둔 경로를 … / 실행 6걸음 · 상태 변경 6걸음 · …

  지원 범위 (4줄, 긴 미지원 문장 2개) / 검증 불가

```
메시지 1개 · 1,096자

  최종 필드: EM존 롱기르수
  잔여: 패 4 · 묘지 2 · 제외 2 · 덱 33 · 엑스트라 4
  특수 소환 제한: 어둠 속성만 (2건 — 스켈레촌 · 디베르)
  🔴 미지원 2건 — 규칙이 막은 것이 아니라 이 저장소에 그 규칙이 없다는 뜻입니다 (사유는 상세 기록).
  🔴 사람이 적어 둔 경로를 끝까지 밟았다는 뜻이고, **최선 전개도 이 패로 가능한 전개 전부도 아닙니다.**
  ⚠️ 검증 불가 2건 — **문제 없음이 아닙니다** (상세 기록에 목록).
🎞 **전개 보기: 아직 없습니다** — … 🔴 **엔진 실행은 정상입니다**
📎 전체 기록은 첨부 `combo-detail.txt`
🧾 전개 기록은 첨부 `combo-replay.json`
첨부 2개 — combo-detail.txt (10,236자) · combo-replay.json (19,078자)
```

🔴 **줄인 것이 아니라 옮긴 것이다.** 6-AE 의 긴 요약
(`render_opening_brief`)은 **지우지 않고 상세 기록 첨부의 첫 절**이 되었다
(그래서 첨부가 8,515자 → 10,236자로 **늘었다**). 미지원 사유의 긴 문장 ·
걸음별 판정 · 멈춘 이유 · 검증 한계 목록이 한 줄도 사라지지 않았다.

### 4.3 "전개 보기" 를 내지 않는 이유

🔴 **실제로 공유 가능한 리플레이를 만든 적이 없으므로 링크를 내지
않는다.** 사이트 첫 화면 주소를 이 전개의 재생 링크처럼 적지도 않는다 —
그 주소는 이 전개를 열지 못한다. 대신 한 줄로 **외부 연동이 없다**는 것과
**엔진 실행은 정상**이라는 것을 함께 적는다. 둘은 다른 사실이다.

전개 기록 파일을 만들지 못한 경우(`COMBO_REPLAY_FAILED_NOTICE`)와 전송
상한 때문에 붙이지 못한 경우(`COMBO_REPLAY_SKIPPED_NOTICE`)도 따로 적는다.
🔴 **어느 경우에도 실행 결과와 상세 기록은 그대로 간다.**

## 5. 실제 재현한 전개와 일치 여부

재현 대상은 **기존 고정 경로** `orcust-skeleton-longirsu` 하나이고, 패와
레시피를 바꾸지 않았다 (`docs/orcust-skeleton-revival-and-longirsu-line.md`
§5.1 과 같은 입력).

실행 실측 (6/6단계):

| # | 걸음 | 기록된 사건 |
| --- | --- | --- |
| 1 | 기르수 일반 소환 | `monster_summoned` (HAND → MZONE) |
| 2 | 기르수 ① | `zone_moved` 디베르 DECK → GRAVE · `zone_shuffled` |
| 3 | 디베르 ① | **비용** `zone_moved` 디베르 GRAVE → REMOVED / **해결** `monster_summoned` 스켈레촌 DECK → MZONE · `special_summon_limited` |
| 4 | 갈라테아 링크 소환 | 소재 2장 MZONE → GRAVE · `monster_summoned` EXTRA → EMZONE |
| 5 | 스켈레촌 ① (대상 #75) | **비용** 스켈레촌 GRAVE → REMOVED / **해결** 기르수 GRAVE → MZONE · `special_summon_limited` |
| 6 | 롱기르수 링크 소환 | 소재 2장 (EMZONE · MZONE) → GRAVE · `monster_summoned` EXTRA → EMZONE |

🔴 **이 목록을 애니메이션에 하드코딩하지 않았다** — 위 표는 실행 기록에서
뽑은 것이고, 요약 한 줄(`전개: …`)도 **수락된 걸음**에서 만든다. 경로가
중간에 막히면 그 줄도 거기까지만 적힌다.

**일치 여부**: `verify_replay` 가 기록만으로 최종 판을 재현해 실제

30741503 · 롱기르수 76145142) 를 판에 올릴 방법이 지금 없다.

### 11.5 사이트에서 재생한 것과 규칙 적법성은 다른 사실이다

🔴 §11.3 에서 재생된 것은 **샘플 덱으로 만든 두 걸음짜리 시연**이고, 이
저장소의 전개가 아니다. 그리고 이 사이트는 **수동 재현 도구**이지 규칙
판정기가 아니므로, 여기서 카드가 움직였다는 것이 그 움직임이 실제 게임
규칙에서 적법하다는 뜻이 아니다.

구분해서 적는다.

| --- | --- |

### 12.3 사이트 조작 순서 — **실행 기록에서 뽑았다**

🔴 **예상 흐름이 아니라 기록이 기준이다.** 개체 번호(`#`)는 기록의
`instance` 이고, 같은 이름이 여러 장일 때 **어느 장인지**를 그것으로
가린다.

| # | 사이트에서 할 일 | 기록의 근거 |
| --- | --- | --- |
| 1 | 패의 **기르수 #75** → 몬스터존1 (앞면 공격) | `monster_summoned normal` |
| 2 | 기르수 #75 **효과 발동 표시**(더블클릭) → 덱의 **디베르 #19** → 묘지 | `effect 69811710:e[0]` · `send_to_grave` |
| 3-a | **비용**: 묘지의 **디베르 #19** → 제외 | `cost_payment 57835716:e[0]` · `banish` |
| 3-b | **해결**: 덱의 **스켈레촌 #6** → 몬스터존2 (앞면 공격) | `effect` · `special` |
| 4 | **링크 소재**: 기르수 #75 · 스켈레촌 #6 → 묘지, 엑스트라의 **갈라테아 #81** → EM존 | `action link_summon` (소재 2장) |
| 5-a | **비용**: 묘지의 **스켈레촌 #6** → 제외 | `cost_payment 21441617:e[0]` · `banish` |
| 5-b | **대상**: 묘지의 **기르수 #75** 를 대상 표시(Shift+더블클릭) 후 → 몬스터존1 | `targets=['#75']` · `effect` · `special` |
| 6 | **링크 소재**: 갈라테아 #81 · 기르수 #75 → 묘지, 엑스트라의 **롱기르수 #84** → EM존 | `action link_summon` (소재 2장) |

🔴 **같은 이름을 혼동하지 않도록 적어 둔다.**

* 2번에서 묘지로 가는 디베르 **#19** 와 3-a 에서 제외되는 디베르는 **같은
  장**이다 (덱 → 묘지 → 제외).
* 5-b 에서 소생하는 기르수 **#75** 는 1번에서 일반 소환했다가 4번에서
  소재로 보낸 **그 장**이다. 덱의 다른 기르수 2장은 움직이지 않는다.
* 스켈레촌 **#6** 은 덱에서 특수 소환되어 소재가 되고, 5-a 에서 **자기
  자신을 비용으로** 제외한다.

* 강조: 🔵 이동 · 🔴 비용 · 🟣 링크 소재 · 🟢 효과 대상.

🔴 **같은 이름을 개체 번호로 가린다.** 5·7번에서 움직이는 기르수는 1번에
일반 소환한 **그 장(#75)** 이고, 덱의 다른 기르수 두 장은 화면에서 한 번도
움직이지 않는다. 묘지에서 제외된 디베르(#19) 와 필드로 나온 스켈레촌(#6)
도 번호로 구분된다.

### 13.3 기록이 없어서 표시하지 못하는 것

| | 화면 |
| --- | --- |
| 섞은 뒤의 덱 순서 | 「섞은 뒤 순서 미기록」 이라고 적는다. 🔴 임의로 정하지 않는다 |
| `zone_moved` 의 칸 번호 · 표시 형식 | 존 안에 두되 **칸을 확정하지 않는다** (「칸 번호 미기록」) |
| 덱의 내용 | 가려진 자리이므로 **장수만** 적는다 |
| 상대의 행동 | 이 경로에서 상대는 언제나 패스한다 — 사건이 없으므로 화면도 비어 있다 |
| 링크 마커 · 공격력 | 기록에 없다. 넣지 않았다 |

🔴 **수락되지 않은 걸음은 아무것도 움직이지 않는다** — 그 걸음은 사건을
만들지 않으므로, 실패한 행동이 성공한 이동으로 그려질 수 없다. 토큰은
`token_created` · `token_vanished` 로만 움직이고, 사라진 토큰은 **묘지가
아니라 판에서 없어진다** (이 경로에는 토큰이 없다).

### 13.4 브라우저 확인 결과

설치된 Chromium 으로 `file://` 로 열어 확인했다. 🔴 **시험 통과가 아니라
화면을 직접 본 결과다.**

| 확인 | 결과 |
| --- | --- |
| 시작 패 5장 · 덱 35장 · 엑스트라 덱 6장 표시 | ✅ |
| 8걸음을 끝까지 넘기기 | ✅ (위 표가 그 실측) |
| 최종 자원이 엔진 기록과 일치 | ✅ (위 표) |
| **되돌아갔다 다시 진행하면 같은 상태** | ✅ 「처음으로」 뒤 8번 눌러 같은 판 — 화면을 통째로 비교해 동일 |
| 카드를 눌러 이름 · 패스코드 보기 | ✅ 「잭나이츠 오르페골 기르수 / 패스코드 69811710 · 개체 #75 / 몬스터/효과 / 지금: P0 패」 |
| 키보드 ← → | ✅ |
| 긴 기록이 기본 화면에서 접혀 있음 | ✅ (미지원 · JSON 원본 둘 다 `open=false`) |
| 자바스크립트 오류 · 경고창 | ✅ **없음** |

시험(`pytest tests/test_replay_viewer.py` → **10 passed**)은 담는 방식 ·
주입 차단 · 외부 자원 없음 · 하드코딩 없음 · 디스코드 첨부를 센다. 🔴 그
통과가 **화면 확인을 대신하지 않는다** — 위 표가 화면 확인이다.

### 13.5 안전

기록은 `<script type="application/json">` 안에 **데이터로만** 들어가고,
화면의 모든 글자는 `textContent` 로 들어간다. 카드 이름에 `</script>` 가
들어 있어도 태그가 끊기지 않는다 (시험 `test_a02` 가 그것을 센다).
사용자가 JSON 을 고쳐야 할 일도, 개발자 도구를 열 일도 없다.

## 14. 뷰어 후속 보완 (Phase 6-AV) — 현재 장면과 최종 결과를 가른다

### 14.1 고친 것

| # | 전에는 | 지금은 |
| --- | --- | --- |
| 1 | 오른쪽 칸이 **시작 화면부터 최종 제한 2건**을 보여 주었다 (`rec.final.summon_limits` 를 그대로 읽었다) | **「지금 장면의 특수 소환 제한」** 칸을 따로 두고 **사건이 등록된 장면부터** 센다. 이전 장면으로 돌아가면 그때 상태로 돌아온다. 최종 쪽은 **「최종 결과의 제한」** 이라고 적고, 그 칸 머리에 *「🔴 전체 실행의 결과입니다 — 지금 보고 있는 장면의 상태가 아닙니다」* 를 붙였다 |
| 2 | 엔진 행동 6개와 재생 장면 8개를 **둘 다 "걸음"** 이라고 불렀다 | **「재생 장면 4 / 8」** 과 **「엔진 행동 3 / 6 · 효과 발동 — 오르페골 디베르 · 효과 해결」** 두 줄로 가른다. 숫자는 기록에서 센다 (장면 = 사건 수, 행동 = `steps` 수) |
| 3 | 「전개 완료」가 시작 화면에도 그대로 떠서 재생이 끝난 것처럼 읽혔다 | 그 표시는 **전체 실행 결과** 칸 안에만 있고, 재생이 끝났다는 표시(**「· 재생 끝」**)는 **마지막 장면에서만** 붙는다 |
| 4 | 강조가 **색깔뿐**이었다 | 카드 위에 **짧은 글자**를 함께 적는다 — `이동` · `코스트` · `소재` · `대상` |
| 5 | 자기 필드와 상대 필드가 같은 모양이었다 | 자기(P0) 좌석에 테두리 · 바탕을 줘서 먼저 눈에 들어오게 했다. 버튼을 키우고(`다음 장면 →`) 존 이름이 잘리지 않게 칸 높이를 넓혔다 |

🔴 **형식도 최소로 늘렸다**: `engine-replay/2` → **`/3`** — `initial` 에
**시작 시점의 특수 소환 제한**을 더했다. 제한은 등록 사건으로만 남아서,
시작값이 없으면 「미기록」과 「제한 없음」을 구분할 수 없다. 🔴 **옛 기록도
그대로 열린다** — `/1` · `/2` 는 시작값 칸이 없으므로 화면이 **「시작 시점
제한 정보 미기록」** 이라고 적고, 재생 중 등록된 것만 보일 때는 *「⚠ 위는
재생 중 등록된 것만입니다」* 를 함께 적는다. **없는 기록을 「제한 없음」으로
단정하지 않는다.**

### 14.2 브라우저 확인 결과 (실측)

`docs/viewer/orcust-skeleton-longirsu.html` 을 Chromium 으로 `file://` 로
열어 장면을 하나씩 넘기며 읽었다.

| 재생 장면 | 엔진 행동 | 지금 장면의 제한 |
| --- | --- | --- |
| 0 / 8 | 0 / 6 · 시작 상태 | 걸린 제한이 없습니다 |
| 1 / 8 | 1 / 6 · 일반 소환 — 기르수 | 없음 |
| 2 / 8 | 2 / 6 · 효과 발동 — 기르수 · 효과 해결 | 없음 |

  제한」** 칸에만 있다.
* **이전 → 다음** 으로 돌아왔을 때 화면 전체(글자 포함)가 **동일**했다.

🔴 **디스코드 전송은 확인하지 못했다** — 봇 토큰도 길드 접속 권한도 없다.
확인한 범위는 응답을 만드는 순수 함수가 첨부 셋을 만든다는 것과, 그 HTML
첨부와 **같은 내용의 파일**을 브라우저에서 연 결과다.

### 14.3 남은 한계

* 칸 번호 없는 이동, 섞은 뒤의 덱 순서, 링크 마커·공격력은 여전히 기록에
  없어서 **미기록**으로 적는다 (§13.3).
* 제한의 **해제·만료** 정보가 기록에 없다. 걸린 뒤에는 계속 걸린 것으로
  그린다 — 🔴 임의로 풀지 않는다.
* 커밋된 두 HTML 은 `python3 -m scripts.make_replay_viewer` 가 만든 것과
  같다. 생성 코드를 고치면 **두 파일을 다시 만들어야** 한다.

## §15. 후속 — 갈라테아 자체 리플레이 화면 (Phase 6-AW)

§13 · §14 의 전개 뷰어는 **텍스트 카드와 「다음 장면」 버튼**뿐이었다.
사용자가 원한 것은 그것이 아니라 **실제 카드 그림이 있는 듀얼 필드에서
자동 재생되는 화면**이었고, 6-AW 에서 그렇게 다시 만들었다.

지금 그 화면의 문서는 **`docs/replay-viewer.md`** 다. 카드 그림의 출처와
이용 조건, 공유 엑스트라 몬스터 존의 대응, 기록과 연출의 구분, 브라우저
확인 결과, 공개 링크에 남은 조건이 거기 있다.

🔴 **이 문서(§1~§14)는 외부 Duel Simulator 에 대한 조사 기록으로 남는다.**
리플레이 화면은 그 사이트에 등록하는 기능이 아니다 — 이 저장소의 기록을
이 저장소의 코드로 재생하는 갈라테아 자체 화면이고, 둘은 서로를 대신하지
않는다.
