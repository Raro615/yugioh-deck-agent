```

            │
            ▼
        LuaScriptInfo ─▶ CardRepository ─▶ card.script
            │
            ▼

            │   effects / resolution_effects / unbound_effects
            │   analysis.handler_binding (카드 요약)
            ├──────────────▶ app/main.py::cmd_analyze        ← 🔴 읽지 않았다
            └──────────────▶ scripts/update_cards.py::main   ← 🔴 버렸다
```

|---|---|---|

## 3. 상태 정보가 소실되던 위치 — 정확히 세 곳

### 3.1 🔴 CLI 가 상태를 읽지 않았다 (`app/main.py::cmd_analyze`)

증명되지 않은 블록은 `effects` 에도 `resolution_effects` 에도 들어가지 않는다
(3-F-37 이 의도한 것이다 — `is_registered` 를 지어내지 않기 위해). 그래서
사용자 눈에는 **그냥 효과가 적게 보였다.** 왜 적은지는 어디에도 없었다.

### 3.2 🔴 갱신이 분석 결과를 버렸다 (`scripts/update_cards.py::main`)

```python
analyzer.analyze(card)      # ← 반환값을 받지 않는다
analysed += 1
```

호출은 했으므로 결합 상태는 **계산됐고 즉시 버려졌다.**

### 3.3 🔴 상태 요약에서 행 하나가 빠져 있었다 (`summarise()`)

라벨 표에 `LUA_VERIFIED` · `TEXT_DERIVED` · `UNAVAILABLE` 셋만 있었고
`NO_EFFECT` 가 없었다. 실측:

```
lua_verified 12,687 · text_derived 756 · no_effect 684   합계 14,127
출력된 행만 합치면           12,687 + 756 + 0 = 13,443   ← 684장이 사라졌다
```

🔴 상태 요약이 **자기 자신과 어긋나는** 것은 이 Phase 의 §5-5("기존 출력과 새
상태 요약이 모순되지 않는가")에 직접 걸리므로 함께 고쳤다.

## 4. CLI 출력 변경 (`app/main.py::cmd_analyze`)

효과 목록 뒤, 구조화 정도 앞에 **한 블록**을 넣었다.

### 4.1 전부 증명된 경우 — 한 줄

```
  결합 상태  : 정상 연결 (블록 1개 전부 증명됨)
```

### 4.2 어긋난 경우 — 상태별로 다른 안내

```
  🔴 결합 상태  : 증명된 블록 0/2
      · 대응 불일치 확인 2개 [e1, e2]
        파싱 시점의 스크립트와 분석 시점의 스크립트가 서로 다릅니다. ``--scripts`` 경로와 해당 ``c*.lua`` 를 확인하세요.
      (증명되지 않은 블록은 위 효과 목록에 넣지 않았습니다 — 등록/해결 중 어느 쪽이라고 주장할 근거가 없기 때문입니다.)
```

🔴 **건수는 세 목록 전부에서 실제 필드를 읽어 센다.** "`effects` 에 있으면
`MATCHED`" 라고 가정하지 않는다 — 그 가정이 깨지는 날 조용히 틀린 요약을
내게 된다 (`test_14`). 합이 블록 수와 같은지도 테스트가 확인한다 (`test_13`
5개 사례, `test_15`).

🟢 **블록이 없는 카드는 결합 줄을 내지 않는다** — 어긋날 자리가 없는데 상태를
적으면 소음이다 (`test_16`). Lua 가 없는 카드의 출력은 그대로다 (`test_17`).

## 5. 카드 갱신 요약 변경 (`scripts/update_cards.py`)

### 5.1 분석 결과를 들고 있다가 요약한다

```
  변경된 카드 14장만 다시 분석했습니다.

  효과 블록 결합 상태
    정상 연결                 : 10장
    ✗ 대응 불일치 확인           : 2장
      파싱 시점의 스크립트와 분석 시점의 스크립트가 서로 다릅니다. …
    ✗ 대응 관계 증명 불가         : 1장
      블록 식별 정보가 없어 … 파싱 캐시(data/cache/lua_scripts.json)를 다시 만들면 풀릴 수 있습니다.
    ✗ 입력 소스 없음            : 1장
      분석 시점에 스크립트 파일을 읽지 못했습니다. …
    증명되지 않은 블록 7개 (카드 6장: 2511, 32807846, 4997565, 44887817, 56410769 …)
      이 블록들은 등록·해결 효과 어느 쪽으로도 집계하지 않았습니다 — 어느 쪽이라고 주장할 근거가 없기 때문입니다.
```

🔴 **합이 맞지 않으면 요약 자체가 그것을 드러낸다** (`test_22`):
`✗ 상태 합계 3 != 분석 5`.

### 5.2 누락된 상태 행을 채웠다

```
  Lua 검증됨                   : 12,687장
  텍스트 유래 (Lua 없음)           : 756장
  효과 없음 (통상 몬스터·토큰)         : 684장      ← 추가
  분석 근거 없음                  : 0장
```

그리고 표에 **없는** 분석 상태가 실제로 나타나면 그 사실을 출력한다
(`✗ 표에 없는 분석 상태: {...}`). 지금은 없다 (`test_25`).

### 5.3 🔴 갱신의 성공·실패 판정은 바꾸지 않았다

`validate()` 의 계약은 docstring 에 적힌 대로 **"데이터가 덜 모였다는 이유로
카드가 사라지지 않는다"** 이고, 그것은 **카드 레코드의 온전함**에 관한
것이다. 결합 상태는 **효과 분석의 증명 여부**라서 같은 축이 아니다. 그래서
`report_bindings` 는 **보고만** 하고 `problems` 도 종료 코드도 건드리지
않는다 (`test_24` 가 코드로 못 박는다 — `validate` 안에 결합 관련 식별자가
없고, `report_bindings` 안에 `problems`·`return 1`·`raise` 가 없으며 반환값도
없다).

§5-4 가 물은 "부분적인 분석 실패가 전체 갱신을 중단해야 하는가" 는 **기존
계약으로 판단할 수 있다** — 위 축 구분이 그 답이다. 그 판단을 바꾸는 것은
갱신 정책 재설계이고 이번 Phase 의 범위가 아니다.

## 6. 상태별 복구 안내의 의미

안내 문구는 `analysis/effect_model.py` 의 `_BINDING_GUIDANCE_KO` **한 곳**에
있고 두 소비자가 **import 한다.** 🔴 복사본을 두면 한쪽만 고친 순간 두 경로가
서로 다른 안내를 한다 (Phase 3-F-28 이 탐지 정규식에서, 3-F-32 가 `Clone`
형태에서 각각 겪었다). `test_04` 가 두 소비자에 라벨 문자열 리터럴이 **없음**을
확인한다.

| 상태 | 이름 | 뜻 | 복구 안내 |
|---|---|---|---|
| `MATCHED` | 정상 연결 | 대응이 증명됐다. **핸들러가 비어 있어도 이 상태다** | (없음) |
| `MISMATCHED` | 대응 불일치 확인 | **틀렸다** — 두 목록이 서로 다른 텍스트에서 나왔다 | `--scripts` 경로와 해당 `c*.lua` 확인 |
| `UNPROVABLE` | 대응 관계 증명 불가 | **모른다** — 식별 정보가 없다 | 파싱 캐시 재생성 |
| `SOURCE_MISSING` | 입력 소스 없음 | 분석 시점에 파일을 읽지 못했다 | `--scripts` 디렉터리에 해당 파일이 있는지 확인 |

* 🔴 **네 상태를 하나의 성공/실패로 합치지 않는다** — 세 실패 상태를 각각
  넣으면 **세 번 모두 다른 문장**이 나온다 (`test_21`).
* 🔴 **`UNPROVABLE` 과 `MISMATCHED` 가 같은 메시지를 쓰지 않는다** —
  앞은 캐시 재생성, 뒤는 소스 확인이다 (`test_02`, `test_09`).
* 🔴 **원인을 단정하지 않는다.** 어긋났다는 것은 측정된 사실이지만 *왜*
  어긋났는지는 이 자료만으로 알 수 없다 (캐시 노후 · `--scripts` 경로 ·
  소스 편집이 모두 같은 모양을 만든다). 그래서 "확인하세요 / 수 있습니다" 로
  적고 "캐시가 낡았습니다" 로 적지 않는다 (`test_03`).
* 🟢 **빈 핸들러 목록만으로 오류를 내지 않는다.** "핸들러 없는 유효 블록" 은
  정상이고 코퍼스에 9,887개 있다 (`test_07`).
