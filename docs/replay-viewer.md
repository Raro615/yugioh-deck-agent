# 갈라테아 전개 리플레이 화면 (Phase 6-AW)

실행 기록 한 건(`engine-replay/*`)을 **실제 카드 그림이 있는 듀얼 필드에서
자동 재생**하는 정적 HTML 한 장.

🔴 **외부 Duel Simulator 에 등록하는 기능이 아니다.** 그 사이트에 대한 조사는
`docs/duel-simulator-replay-integration.md` 에 따로 있고, 이 화면은 이 저장소의
기록을 이 저장소의 코드로 재생하는 **갈라테아 자체 리플레이 화면**이다. 둘은
서로를 대신하지 않는다.

관련 코드
: `deck/replay_viewer.py` (화면) · `deck/card_images.py` (카드 그림) ·
  `deck/replay_export.py` (기록) · `scripts/make_replay_viewer.py` (만들기) ·
  `app/discord_bot.py` (첨부)

---

## 1. 만드는 법

```bash
# 그림이 담긴 리플레이 (저장소에 커밋하지 않는 자리로 나간다)
python3 -m scripts.make_replay_viewer \
    --line orcust-skeleton-longirsu \
    --out docs/viewer/local/orcust-skeleton-longirsu.html

# 그림 없이 (저장소에 커밋하는 파일은 이 쪽)
python3 -m scripts.make_replay_viewer --line orcust-skeleton-longirsu \
    --no-images --out docs/viewer/orcust-skeleton-longirsu.html

# 이미 있는 combo-replay.json 으로
python3 -m scripts.make_replay_viewer --json combo-replay.json --out 전개.html

# 기록 없이 여는 빈 화면 (브라우저에서 JSON 을 고른다)
python3 -m scripts.make_replay_viewer --empty --out docs/viewer/replay-viewer.html
```

`--offline` 을 주면 **받아 둔 그림만** 쓴다 (네트워크를 쓰지 않는다).

## 2. 화면 구성

```
┌ 지금 행동 ────────────────────────────────┐ ┌ 카드 상세 ┐
│ 장면 n / N · 엔진 행동 k / K              │ │ 그림      │
│ 링크 소환 — 오르페골 갈라테아 · 행동       │ │ 한국어명  │
│ (무엇이 어디서 어디로 갔는지 한 줄)        │ │ 수치·효과 │
│ 강조 근거 — 소재: 엔진 사건 / …            │ └───────────┘
└───────────────────────────────────────────┘ ┌ 장면 목록 ┐
  상대 (P1)  패 · 마법함정 5 · 몬스터 5 ·     │ 0. 시작   │
             필드존 · 덱 · 묘지 · 제외 ·      │ 1. …      │
             엑스트라                          └───────────┘
  ── 공유 엑스트라 몬스터 존 [자신][상대] ──   ┌ 지금 장면의 제한 ┐
  자신 (P0)  몬스터 5 · 마법함정 5 · … · 패    ┌ 전체 실행 결과 ┐
┌ ⏮ ◀ ▶ ▶❙ ── 진행 막대 ── n/N 0.5x 1x 2x 3x ┘ ▸ 접힌 상세들
```

- 필드가 화면의 중심이고, 긴 경고문은 **접힌 상세 영역**으로 내려갔다
  (미지원 목록 · 카드 그림 출처와 누락 · 원본 JSON).
- 「지금 장면의 특수 소환 제한」 과 「전체 실행 결과」 는 **다른 칸**이다
  (6-AV 에서 고친 혼동을 그대로 지킨다).

### 공유 엑스트라 몬스터 존

🔴 엔진은 **좌석마다 `EMZONE` 1칸**을 갖는다
(`engine/vocabulary.py` 의 `ZONE_CAPACITY[Zone.EMZONE] == 1`). 실제 듀얼의
공유 2칸과 대응시키려고, 화면은 **가운데 한 줄에 두 칸만** 그리고

| 엔진 | 화면 |
| --- | --- |
| 좌석 0 의 `EMZONE` | 공유 줄의 **왼 칸** |
| 좌석 1 의 `EMZONE` | 공유 줄의 **오른 칸** |

으로 둔다. 같은 물리적 자리를 양쪽 필드에 **중복 생성하지 않는다.** 한
좌석에 두 장 이상이 들어오면 (엔진이 그렇게 적은 적은 없다) 칸을 지어내지
않고 「칸 미확정 n」 으로 따로 적는다.

## 3. 카드 그림

| | |
| --- | --- |
| 출처 | YGOPRODeck 카드 이미지 서버 (`images.ygoprodeck.com`) |
| 안내문 | <https://ygoprodeck.com/api-guide/> |
| 크기 | `cards_small` (268×391, 한 장 30KB 안쪽) |
| 열쇠 | **패스코드 하나** — 이름 유사 검색을 쓰지 않는다 |
| 보관 | `data/cache/card_images/<패스코드>.jpg` (gitignore) |
| API 키 | **필요 없다** — 코드에도 HTML 에도 비밀값이 없다 |

제공처가 적어 둔 이용 조건 (2026-11 확인):

> NOTE ON IMAGES: Do not continually hotlink images directly from this site.
> Please download and re-host the images yourself. Failure to do so will
> result in an IP blacklist.

> Images are pulled from our image server images.ygoprodeck.com. You must
> download and store these images yourself! Please only pull an image once
> and then store it locally.

> Rate Limiting on the API is enabled. The rate limit is 20 requests per 1
> second.

그래서 이 계층은 **한 번만 받아 보관**하고, 뷰어 HTML 은 그 파일을
`data:image/jpeg;base64,…` 로 **안에 담아** 나간다. 화면을 열 때도 재생할
때도 제공처로 요청이 나가지 않는다 (생성된 HTML 에 `http://` · `https://`
가 **0건**인 것으로 확인했다).

🔴 **커밋하지 않는다.** 카드 그림은 코나미의 저작물이라, 받아 둔 그림도
그림을 담은 HTML 도 저장소에 넣지 않는다 — `.gitignore` 의 룰북 PDF 와 같은
취급이다. 저장소에 들어가는 `docs/viewer/*.html` 은 `--no-images` 로 만든
것이고, 그림이 필요한 사람은 위의 명령으로 자기 자리에서 만든다.

🔴 **누락은 감추지 않는다.** 그림을 구하지 못한 카드는 **이름으로** 그리고,
「카드 그림 출처와 누락」 칸에 누락 패스코드를 적는다. 생성 모델로 카드
그림을 대신 그리거나, 다른 카드의 그림을 그 카드인 것처럼 쓰지 않는다.

디스코드 응답은 `COMBO_IMAGE_FETCH_LIMIT`(24장) 만큼만 새로 받는다 —
상한에 걸린 카드는 이름으로 나가고, 받아 둔 그림은 다음 요청부터 바로
쓰인다.

## 4. 재생 — 장면 · 박자 · 사건

| 말 | 뜻 |
| --- | --- |
| **사건** | 엔진이 적은 journal 한 줄 |
| **장면** | 사건 하나 = 장면 하나. 0번은 시작 판. **장면 수 = 사건 수 + 1** |
| **박자** | 한 장면 안의 연출 단계 (`pre` → `final`) |

`pre` 박자는 **이전 판 위에** 이번 장면의 소재 · 대상 · 발동 카드를 강조만
하고, `final` 박자가 실제로 옮긴다. 그래서 링크 소환이
「소재 강조 → 소재 이동 → 링크 몬스터 등장」 으로 보인다.

🔴 **박자는 판정 상태가 아니다.** 박자를 나눠도 엔진 사건은 하나이고 장면
번호도 하나다 (화면은 앞 박자에 「· 준비」 라고만 덧붙인다).

### 기록과 연출의 구분

화면의 「강조 근거」 줄이 **강조 하나하나가 어디서 나왔는지** 적는다.

| 강조 | 근거 | 엔진 사건인가 |
| --- | --- | --- |
| 발동 | 사건의 `source` | ✅ |
| 이동 | 사건의 delta (`zone_moved` · `monster_summoned` · `card_drawn`) | ✅ |
| 코스트 | `cost_payment` 사건의 delta | ✅ |
| 소재 | 링크 소환 **행동 사건**의 이동 delta | ✅ |
| 사라짐 | `token_vanished` delta | ✅ |
| **대상** | 걸음 기록의 **글자 설명**(`targets`) | ❌ **연출이다** |

🔴 기록에 없는 체인 · 성공 · 해결을 만들어 내지 않는다. 같은 이름의 두 장은
**개체 번호(`#n`)** 로 구분한다 (카드마다 오른쪽 아래에 적는다).

### 칸을 확정하지 않는 자리

- `monster_summoned` 는 칸 번호와 표시 형식이 있으므로 그 자리에 그린다.
- `zone_moved` 는 칸 번호가 없다 — 존 안에 두되 **칸을 확정하지 않고**,
  슬롯이 아니라 「칸 번호 미기록 n장」 트레이에 놓는다.
- 섞인 덱은 「순서 미기록」 이라고 적는다.
- 덱과 상대 패는 **뒷면**으로만 그린다 (가려진 자리).

## 5. 재생 컨트롤의 규율

- **재생 상태(`state.playing`)와 연출 상태(`anim`)는 다른 칸**이다.
- 예약된 타이머는 **언제나 하나**다 (`arm()` 이 먼저 `cancelAnim()` 한다).
  그래서 배속을 바꿔도 사건이 두 번 일어나지 않는다 — 배속 변경은
  **남은 시간만** 다시 재고 장면을 넘기지 않는다.
- 이전 · 다음 · 진행 막대 · 장면 목록은 모두 `seek()` 를 지나고,
  `seek()` 는 진행 중 연출을 **정리하고** 그 장면의 확정 상태를 그린다.
- 「처음으로」 는 0번 장면 = 시작 판을 복원한다.
- 마지막 장면에서 **자동 정지**한다.
- 다른 기록을 열면 (`load()`) 이전 재생 작업을 **취소한다**.
- 🔴 재생 중에 엔진을 다시 부르거나 난수를 쓰지 않는다. 그래서 몇 번을
  재생해도 같은 최종 판이 나온다.

## 7. 공개 링크 — 아직 없다

🔴 **이 저장소에는 웹 서버도 배포 설정도 없다.** `app/` 은 디스코드 봇과
CLI 뿐이고, Dockerfile · Procfile · 호스팅 설정 파일이 하나도 없다
(2026-11 확인). 그래서 **요청별 리플레이 URL 은 제공하지 않는다.**

- 로컬에서 동작하는 재생 페이지까지는 **완성**이다 (파일을 그대로 브라우저
  에서 열면 된다 — 서버가 필요 없다).
- 디스코드 HTML 첨부 방식은 **그대로 유지**한다.
- 🔴 `file://` 나 `localhost` 주소를 **다른 사람이 열 수 있는 공유 링크라고
  말하지 않는다.**
- 🔴 외부 Duel Simulator 주소를 갈라테아 결과 링크로 **대체하지 않는다.**

공개 링크를 붙이려면 남은 조건은 이것뿐이다 (아직 하지 않았다):

1. **정적 파일을 올릴 자리** 하나. 뷰어는 서버 로직이 필요 없는 HTML 한
   장이라, 정적 호스팅이면 충분하다.
2. **요청별 경로**. `/replay/<토큰>` 으로 `combo_response` 가 만든 HTML 을
   올리고 그 URL 을 응답에 적는다. 🔴 다른 요청에 고정 예제 링크를 붙이지
   않는다 — 실제로 올라간 파일의 주소만 적는다.
3. **수명과 접근 범위**. 전개 기록에는 사용자의 덱 구성이 들어간다. 언제
   지울지, 누가 열 수 있는지를 정하지 않은 채로 올리지 않는다.
4. **카드 그림의 재배포 판단**. 지금은 HTML 안에 담아 요청한 사람에게만
   보낸다. 공개 주소에 올리는 것은 범위가 다르므로 따로 판단해야 한다.

새 유료 서비스에 가입하거나 임의의 외부 자리에 파일을 공개하지 않았다.

## 8. 디스코드 연결

`/combo` 응답은 같은 기록의 **네 가지 표현**을 보낸다.

1. 짧은 요약 (메시지)
2. `combo-detail.txt` — 사람이 읽는 상세
3. `combo-replay.json` — 기계가 읽는 기록
4. `combo-replay.html` — **이 리플레이 화면** (그림 포함, 617KB 수준)

🔴 **디스코드 실제 전송은 확인하지 않았다.** 봇 토큰이 없는 자리라
`combo_response()` 가 만드는 첨부와 메시지를 시험으로 확인한 것이 전부이고,
그것을 디스코드 실사용 확인이라고 부르지 않는다.
