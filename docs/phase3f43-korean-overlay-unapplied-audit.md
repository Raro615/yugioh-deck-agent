## 3. 171 과 7 — 집계 기준의 차이

### 3.1 네 집합을 구분한다

```
cards.cdb 행                       14,755
  └─ OfficialDatabaseSource.load()  14,514   (토큰 241개 제외, include_tokens=False)
       └─ CardRepository._cards      14,520   (+ c*.lua 만 있는 레코드 6개)
            └─ all_cards()           14,127   (− alias 판본 393개)

ko 항목                             13,899
  └─ apply() 가 닿은 레코드          13,892   ← 반환값 = KOREAN_OVERLAY 부착 수
  └─ 진짜 미적용                          7
```

**검산: 13,892 + 7 = 13,899** (`test_04`). 두 집합은 서로소이고 합이 전체다
(`test_05`).

### 3.2 이전 보고서가 센 것

```
entries − canonical 카드   = 171   ← 이전 보고서의 "미적용"
entries − 닿은 레코드       =   7   ← 실제 미적용
차이                       = 164
```

`CardRepository.build()` 는 `korean_source.apply(cards)` 를 호출하는데 그
`cards` 는 `official.load()` 의 **전체 레코드**다. alias 판본도 거기 있으므로
오버레이가 닿는다. 그런데 `all_cards()` 는 canonical 만 돌려준다. 그래서
canonical 을 기준으로 세면 **적용된 alias 판본이 "미적용" 으로 잡힌다.**

네 수가 모두 다르다는 사실 자체를 `test_01` 이 못 박아, 다시 섞이지 않게 했다.

### 3.3 164개가 정상 적용된 근거

전수 확인 (`test_07`~`test_10`):

| 확인 항목 | 결과 |
|---|---|
| `alias != 0` | **164 / 164** |
| alias 대상이 canonical 카드 | **164 / 164** |
| 한국어 **이름**을 받음 | **164 / 164** |
| 한국어 **텍스트**를 받음 (원문은 `desc_en` 에 보존) | **164 / 164** |

대표 사례 (`test_11`, `test_12`):

```
판본 295517  alias → 22702055 (canonical)
  판본 자체의 name_ko = '전설의 도시 아틀란티스'
  원본의     name_ko = '바다'
  repo.canonical(판본).id == 22702055  이고 그 카드도 한국어를 갖는다
```

즉 **"조용히 버려진다" 는 서술은 틀렸다.** 판본과 원본이 각각 자기 한국어
데이터를 받는다.

## 5. DB 조회 및 production 연결 경로

```
data/ko/ko-KR.json
  └─ KoreanTextSource.autoload() → load() → entries {passcode: {name, desc}}
                                                    13,899개

data/cards.cdb (14,755행)
  └─ OfficialDatabaseSource.load(include_tokens=False) → 14,514 레코드
                                                 (토큰 241개 제외)
       │
CardRepository.build()
  ├─ cards = official.load()                       14,514
  ├─ _attach_scripts(cards, scripts)               (+ Lua 전용 6개 → 14,520)
  ├─ korean_source.apply(cards)   ← 🔴 **전체 레코드**가 대상 (alias 포함)
  │     for cid, entry in entries.items():
  │         card = cards.get(cid)
  │         if card is None: continue              ← 미적용 7개가 여기서 빠진다
  │         ...  card.sources.add(KOREAN_OVERLAY)
  │     return applied                             13,892
  └─ all_cards() → canonical 만                    14,127
```

**미적용의 직접적 원인**: `apply()` 의 `cards.get(cid)` 가 `None` 을 돌려주는
것. 그 7개 passcode 가 `cards` 에 없고, `cards` 에 없는 이유는 `cards.cdb` 에
행이 없는 것이다. 수집기·저장 데이터·저장소 셋 중 **저장소 입력(카드 DB)**
단계의 범위 문제다.

어댑터가 거르는 241개는 **토큰**이고 한국어 항목과 겹치지 않는다
(`test_21`). 그래서 `LINKING_ERROR` 가 공집합이다.

## 6. 확인된 사실과 입증되지 않은 가설의 구분

**확인된 사실 (재현 가능)**

* 13,899 = 13,892 적용 + 7 미적용.
* 164개 alias 판본은 이름·텍스트 모두 적용 — 164/164.
* 7개는 `cards.cdb` 14,755행에 없고, `load()` 결과에도 없다.
* 7개 전부 수집기 캐시에 공식 CID 가 있다.
* `LINKING_ERROR`·`ID_MISMATCH`·`COLLECTOR_ERROR`·`UNRESOLVED` 모두 공집합.
* 7개는 repository 에 카드가 없어 표시 대상이 아니다.

**입증되지 않은 가설 (기록만)**

* 🟡 "7개가 `cards.cdb` 스냅숏보다 **나중에 나온 카드**이기 때문" — 그럴
  법하지만 이 저장소 안의 증거로는 확정할 수 없다. cdb 의 생성 시점과 공식
  출시일을 비교할 자료가 없고, 공식 DB 재수집은 §5 가 금지한다. 그래서
  "스냅숏에 없다" 까지만 적는다.
* 🟡 "다른 passcode 로 같은 카드가 DB 에 있을 가능성" — 이름이 비슷하다는
  이유로 동일 카드라고 판정하지 않았다 (§3 금지). ID 관계로 확인할 수 있는
  것은 "alias 관계가 없다" 뿐이고, 그것은 확인했다.
