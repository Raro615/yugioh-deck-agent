## 3. Action Independence — **PASS**

구조적으로 불가능하다: 서명에 행위가 없고, 소스에 `PlayerAction` ·
`PlayerActionKind` · `action` · `kind` 가 **0건**.

실제로도 확인했다. 같은 관측을 **두 경로**로 만들어 비교했다.

```
경로 A  패에서 일반 소환                 → canonical_state X
경로 B  같은 자리에 직접 배치 + 소환권 기록 → canonical_state X   (같다)

평가 A = (1, 2400)   평가 B = (1, 2400)   → 같다
```

역사가 다른 두 `GameState` 가 같은 관측을 주면 같은 점수다. 같은 관측을
50회 평가해도 값이 하나다 (상태를 들고 있지 않다).

실제 듀얼 3판에서 시뮬레이션한 미래 1,048개를 관측별로 모아 보니 **같은
관측에 두 점수가 나온 경우가 0회**였다.

## 4. Side-to-Move — **읽지 않는다** 🟠 STRUCTURAL-128 (신규)

## 7. Hand / Resource — 🟠 STRUCTURAL-129 (신규)

| 판 | 내 패 항 |
|---|---|
| 내 패 0 / 1 / 2 / 3 장 | `0` / `+200` / `+400` / `+600` |

두 자리의 점수를 견주는 어떤 계산(minimax · 후회 · 상대 관점 추정)도 지금
값으로는 성립하지 않는다. Depth-1 에서는 드러나지 않고 Depth-2 에서 드러난다.

## 15. RuleBased vs Search (§18) — 관측만 기록

| 상황 | RuleBased | Search | 같은가 |
|---|---|---|---|
| 1900 vs 1500 (이기는 공격) | `ATTACK` | `ATTACK` | 같음 |
| 1500 vs 1900 (지는 공격) | `ATTACK` | `END_PHASE` | **다름** |
| 소환 vs 세트 | `NORMAL_SUMMON` | `NORMAL_SUMMON` | 같음 |
| 욕망의 항아리 | `ACTIVATE_EFFECT` | `SET_SPELL_TRAP` | **다름** |
| 무정한 말살 (대상 2개) | `ACTIVATE_EFFECT` | `SET_SPELL_TRAP` | **다름** |

**어느 쪽이 옳다고 적지 않는다.** 분해하면 차이의 원인이 **두 가지**다.

### (a) 미래를 보는가 — "지는 공격" 자리

규칙 기반에는 "지는 공격을 피한다" 는 규칙이 **없다**. `higher-attack-first`
는 공격자의 공격력만 보고 대상의 공격력을 보지 않는다. 탐색은 미래를 보고
`ATTACK(-2800) < END_PHASE(-400)` 을 읽어 넘긴다.

### (b) 🟠 STRUCTURAL-123 — 두 정책이 **다른 양**을 센다

| | 세는 것 | 단위 | 자릿수 |
|---|---|---|---|
| RuleBased | **지금 판**의 카드 수치 | 자체 점수 | `BOARD_PRESENCE` 10,000,000 · `ATK_WEIGHT` 1000 |
| Search | **미래 관측**을 LP 로 환산 | LP | `MONSTER_IN_LP` 500 · `ATK_IN_LP` 1 |

`BOARD_PRESENCE / MONSTER_IN_LP = 20,000` — 단위도 자릿수도 다르므로 **두
점수를 견줄 수 없다.** 그리고 규칙 기반은 규칙이 보지 않는 후보(세트 · 발동)
전부에 0 을 주고, 0 끼리는 `canonical_state` 순서로 갈린다 —
`"activate_effect" < "end_phase" < "set_spell_trap"` 이므로 **알파벳 순서가
정책이 된다**(STRUCTURAL-123 을 Phase 3-E-3 이 처음 관찰했다).

실제 패배 경로가 되었는데**(Phase 3-E-1-B 에서 모든 듀얼이 LP 0 으로 끝남)
상수는 그대로다. 그래서 탐색이 드로우 효과를 **한 번도** 고르지 않는다.

## 21. 다음 Phase 제안 — 하나만

### **STRUCTURAL-115 — 뒷면 카드 평가의 정합성** 을 먼저 해결할 것을 제안한다.

여섯 문제 중 이것 하나만이 **"보고가 사실과 다르다"** 다. 나머지 다섯은
"설계가 이렇게 되어 있다" 이고, 그 설계를 바꿀지는 별도의 판단이 필요하다.
115 는 판단이 필요 없다 — 지금 코드가 **스스로 모순**이다.

그리고 115 를 고치면 130(`partial` 의 93.3%가 이 거짓 보고)이 함께 줄어들어,
**다른 문제를 측정할 수 있는 상태**가 된다. 지금은 `partial` 이 늘 참이라
"이 평가는 불완전하다" 를 읽을 수 없다.

고칠 때 정해야 하는 것은 **셋 중 하나**이고, 그 선택에 승인이 필요하다.

1. 뒷면 몬스터의 공격력을 **세지 않는다** — `excluded` 의 문장이 참이 된다.
   대신 `normal_summon` 과 `set_monster` 의 점수가 갈리고, 세트가 소환보다
   낮아진다 (공격력이 빠지므로)
2. **수비력을 센다** — 뒷면 수비 표시의 실제 역할에 맞다. 다만 수비력을 LP 로
   환산하는 근거를 새로 정해야 한다 (`ATK_IN_LP` 처럼 1:1 이라고 말할 수 없다)
3. 공격력을 **그대로 세고 `excluded` 문장을 지운다** — 지금 동작을 유지하고
   보고만 사실에 맞춘다. 가장 작은 변경이지만, "내 뒷면은 상대에게 안 보인다"
   는 비대칭이 점수에 남는다

**1번을 권한다** — 모듈 설명이 이미 1번을 의도라고 적고 있으므로, 코드를
설명에 맞추는 것이 가장 작고 근거가 분명한 변경이다. 다만 세트의 점수가
내려가면 AI 의 선택이 달라지므로 그 영향을 함께 측정해야 한다.

**128 · 129 는 Depth-2 가 필요해질 때 함께 다루는 것이 맞다.** 둘 다
"상대 차례를 어떻게 셀 것인가" 라는 같은 질문의 두 얼굴이고, Depth-1 에서는
증상이 드러나지 않는다.
