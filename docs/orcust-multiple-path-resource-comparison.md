# 복수 전개 경로 수집과 최종 자원 비교 (Phase 6-AI)

같은 초기 상태에서 **서로 다른 성공 결과 여럿**을 모으고, 각 결과를 새 초기
상태에서 재생하고, 재생된 실제 상태를 근거로 **남은 자원의 차이**를 적는
단계다. 앞 단계(6-AH · 6-AH 보완, `docs/orcust-first-bounded-search.md`)가
만든 제한 탐색을 **그대로** 쓴다.

> 🔴 **이 단계는 최강 전개·승률·방해 수 평가가 아니다.** 평가 함수가 없고,
> 임의의 점수로 전개를 강한 순서처럼 정렬하지 않는다. 아래의 모든 표는
> **남은 자원을 늘어놓은 것**이고 순위가 아니다.

## 1. 복수 성공 결과 수집

### 1.1 별도 탐색기를 만들지 않았다

복수 결과 수집은 **같은 탐색기**가 한다. 고리는 `BoundedSearch._drive`
하나이고, 노드를 펼치는 `_open`, 중복 제거 `node_key`/`admit`/`superseded`,
해결 중 선택 분기 `_attempts`/`_apply_once` 는 단일 결과 모드와 **같은
코드**를 지난다. `run_many` 가 더하는 것은 셋뿐이다.

1. 목표에 닿은 자리를 **값으로 모아 두고**(`_collect`) **그 분기를 더
   펼치지 않는다.**
2. 결과 수 상한(`SearchBudget.max_results`).
3. 탐색이 **끝난 뒤** 모은 결과를 재생한다(`rerun_results`).

단일 결과 모드는 한 글자도 달라지지 않았다. `_open` 의 목표 분기가
`self.budget.many` 가 거짓이면 예전처럼 `return path, child_duel, verdict`
로 **그 자리에서** 멈춘다(시험: `test_e08`).

### 1.2 목표에 닿은 분기는 더 펼치지 않는다

비교하는 것은 "목표에 **처음** 도달하고 체인과 필수 처리가 정리된 상태"다.
그래서 목표 상태를 스택에 쌓지 않는다 — 쌓으면 **같은 경로에서 목표 달성
뒤 세트만 더 한 결과**가 별개의 "좋은 전개" 로 늘어난다.

격리 그래프로 그 사실을 고정했다(`GOAL_THEN_MORE`: `R→G1`, `G1→G1b`, 둘 다
목표). 결과는 **1개**이고, 탐색이 `G1→G1b` 간선을 펼친 기록이 없다
(`test_a02`).

### 1.3 예산 다섯 칸과 종료 사유

| 칸 | 기본값 | 뜻 |
|----|--------|-----|
| `max_depth` | 6 | 경로 길이 |
| `max_nodes` | 200 | 펼친 노드 수 |
| `max_seconds` | 300 | 탐색 시간 |
| `max_choice_branches` | 4 | 한 행동의 해결 중 선택 대안 각본 수 |
| `max_results` | **1** (복수 모드 권장 3, 상한 `RESULTS_CAP=5`) | 모을 결과 수 |
| `max_rerun_seconds` | 180 | **재생** 실행 시간 |

🔴 **결과 수 상한에 닿아 멈춘 사실은 종료 사유에 남는다.**
`budget_hit` 에 `max_results=N` 이 적히고 `MultiSearchOutcome.hit_result_cap`
이 참이 된다. 그래서 그 결과 묶음은 "가능한 전부" 가 아니다(`test_a03`).

🔴 **"찾은 결과가 있음" 과 "탐색을 끝까지 수행함" 을 가른다.** 앞의 것은
`reached`(결과가 비어 있지 않은가), 뒤의 것은 `search_exhausted` 다.
`search_exhausted` 는 **네 가지가 모두 참일 때만** 참이다 — 스택이 비어서
끝났고, 예산에 걸린 칸이 없고, 오류가 없고, **확인하지 못한 해결 중 선택
대안도 없다**. `termination` 은 **고리가 왜 멈췄는가**이고, 복수 모드에서는
결과를 찾았더라도 `exhausted` 나 `budget_exceeded` 로 남는다(목표 분기를
펼치지 않고 고리를 계속 돌리기 때문이다).

🔴 **예산이 끝나도 찾은 결과는 보존한다**(`test_a04`).

🔴 **중복을 발견했다는 이유로 서로 다른 결과 수가 늘지 않는다.** 같은
결과에 닿은 다른 경로는 `duplicate_results` 로 따로 센다(`test_a06`).

## 2. 결과 동일성과 대표 경로

### 2.1 두 중복 제거는 목적이 다르다

| | `node_key` (6-AH) | `outcome_key` (6-AI) |
|---|---|---|
| 묻는 것 | 이 상태를 **또 펼칠** 필요가 있는가 | 이것이 **같은 성공 결과**인가 |
| 체인 중 | `None` — 중복 제거를 **끈다** | **거절한다**(정리되지 않은 자리를 성공으로 세지 않는다) |
| 쓰는 곳 | `_open` 의 자식 등재 | `_collect` 의 결과 합치기 |

🔴 **기존 `node_key` 를 무조건 재사용하지 않았다.** 두 함수가 보는 것이 겹치는
부분(상태 해시 · 고를 사람 · 진행 단계 · 우선권 창 · 그 자리의 허용 후보
집합)은 같지만, 체인 중인 자리를 다루는 방식이 **정반대**다. 탐색 중에는
"모르니까 펼쳐 둔다" 가 안전하고, 결과 집계에서는 "모르니까 세지 않는다" 가
안전하다(`test_b01`).

### 2.2 동일성은 양쪽 자리의 실제 상태를 본다

`outcome_key` 의 상태 해시는 `GameState.state_hash()` 이고, 그것은
`canonical_state()` 에서 나온다 — 양쪽 플레이어의 모든 존(패 · 덱 ·
엑스트라 · 몬스터 존 · 엑스트라 몬스터 존 · 마법함정 존 · 묘지 · 제외 ·
필드 · 펜듈럼), 턴과 단계, 그리고 `uses` · `rule_uses` · `summon_uses`
전부가 들어 있다.

🔴 **카드 장수나 카드명 목록만 같다는 이유로 합치지 않는다. 필드가 같아도
사용 제한이 다르면 다른 결과다.** 격리 그래프로 그 경우를 만들어 고정했다
(`SAME_FIELD_OTHER_USES`: 두 꼬리표의 **카드 ID 목록이 완전히 같고**
기록된 카드명 사용만 다르다 → 결과 **2개**, 합친 경로 0개;
`test_b02` · `test_b03`).

🔴 **안전하게 판단할 수 없으면 따로 둔다.** `_is_settled` 가 거짓인 자리는
결과로 세지 않고(위), 개체 번호를 지우는 공격적 정규화는 하지 않았다.

### 2.3 대표 경로

같은 결과에 닿은 경로가 여럿이면 **대표 하나**만 제시한다. 기준은
`representative_order` 이고, **명시적이고 결정론적**이다.

1. 걸음이 적은 쪽
2. 같으면 행동 열쇠들의 안정된 순서
3. 같으면 해결 중 선택들의 안정된 순서

🔴 **발견한 경로 중의 대표이고, 전체 최단 경로 보장이 아니다.** 탐색이 보지
않은 더 짧은 경로가 있을 수 있다.

🔴 **대표가 교체될 수 있으므로 재생은 탐색이 끝난 뒤에 돈다.** 중간에
돌리면 교체된 대표가 검증되지 않은 채 보고된다. 격리 그래프
`SAME_GOAL_TWICE`(긴 경로가 먼저, 짧은 경로가 나중에 같은 상태에 닿는다)로
교체와 "교체된 쪽이 재생된다" 를 둘 다 고정했다(`test_b04` · `test_c05`).

### 2.4 남은 한계 — 잔여 중복

이 기준은 **"지금 상태가 같다"** 만 본다. 상태가 다르면 따로 세므로
**사람 눈에 "사실상 같은 전개"** 가 둘로 남을 수 있다 — 실측에서도 그런
쌍이 나왔다(§5.1 의 결과 2 와 결과 3: 세트 한 장만 더 했고 그 외의 차이가
없다). 🔴 이것을 "서로 다른 좋은 전개 두 가지" 로 읽지 말아야 한다. 그
판단(어느 차이가 의미 있는가)은 평가에 속하고, 이번 단계에 평가는 없다.

## 3. 실제 자원 요약

`summarize_resources(duel, seat)` 가 그 자리에서 **값**을 뜬다.

🔴 **살아 있는 `Duel` 을 공유하지 않는다.** 돌려주는 `ResourceSummary` 는
frozen 이고 어떤 칸에도 `Duel` · `Simulator` 가 없다 — 공유하면 뒤의 탐색이
그 판을 더 밟았을 때 요약이 **조용히 달라진다**(`test_d07`).

### 3.1 적는 것

| 자리 | 내용까지 | 장수만 |
|------|----------|--------|
| 자신 | 패 · 몬스터 존 · 엑스트라 몬스터 존 · 마법함정 존 · 필드 존 · 펜듈럼 존 · 묘지 · 제외 | 남은 메인 덱 · 엑스트라 덱 |
| 상대 | 몬스터 존 · 엑스트라 몬스터 존 · 마법함정 존 · 필드 존 · 펜듈럼 존 · 묘지 · 제외 (**앞면만 정체를 적는다**) | 패 · 덱 · 엑스트라 |

여기에 턴 번호와 단계, 상태 해시, **엔진에 기록된 사용 제한**(효과별 ·
카드별 · 카드명별 · 소환별 · 규칙별)과 **일반 소환권 사용 여부**가 함께
들어간다.

### 3.2 지우지 않는 것

- 같은 이름 여러 장은 **각각** 남는다(개체 번호 · 앞뒷면 · 표시 형식 ·
  칸 순서까지).
- 토큰도 한 칸으로 남는다(실측: 상대 몬스터 존의 `[46647145]`).
- 🔴 **입력에 상대의 비공개 정보가 없으면 만들어서 평가하지 않는다.**
  상대의 패 · 덱 · 엑스트라는 **장수만**이고, 상대 필드의 뒷면 카드는
  정체를 적지 않는다(`CONCEALED_CARD`) — "없다" 가 아니라 **"모른다"** 다
  (`test_d06`).

### 3.3 한국어 이름은 표시 층이 붙인다

요약은 **카드 ID 만** 들고 있다. 한국어 이름은 `deck/report.py` 가
`repository` 로 붙인다 — `agent/` 는 표시 경계 감사의 제한 대상이고, 저장소를
주지 않으면 ID 만 적는다(`test_e03`: 저장소를 주면 "오르페골 갈라테아
[30741503]", 주지 않으면 "[30741503]").

### 3.4 요약에 담기지 않는 차이

🔴 **실제 차이를 요약으로 표현할 수 없으면 "같다" 고 적지 않는다.** 두 결과가
비교 항목에서 모두 같게 보이면, 보고는 "차이를 찾지 못했다" 와 **"두 결과는
엔진 상태가 다르다(그래서 따로 셌다)"** 를 함께 적고 상태 해시와 전체 존
목록을 보라고 적는다.

## 4. 비교와 설명

같은 초기 상태에서 나온 **검증된 성공 결과들** 사이에서만 비교한다.

비교표의 항목: 행동 수(와 해결 중 선택 횟수) · 남은 패 장수와 구성 · 자신
필드 · 자신 마법함정 존 · 상대 필드에 남긴 칸 · 자신 묘지 구성 · 자신 제외
구성 · 남은 덱 장수 · 일반 소환권 사용 · 기록된 사용 제한 · **재생 검증
여부**.

### 4.1 적지 않는 것 — 🔴 금지 목록

| 금지 | 이유 |
|------|------|
| 패와 필드 장수를 더한 **총점**으로 "자원 N" 을 만들고 강하다고 적는 것 | 자원의 종류가 다르다. 더하면 평가가 되고, 평가 함수가 없다 |
| 묘지·제외에 간 카드를 **손실**로 세는 것 | 이 덱에서 묘지는 자원이다. 손실로 세면 틀린 전제가 들어간다 |
| 상대 필드의 토큰을 **항상 나쁜 것**으로 세는 것 | 그 칸이 무엇을 막고 무엇을 돕는지는 이 단계에서 세지 않는다 |
| 쓰지 않은 효과를 **지금 쓸 수 있다 / 다음 턴에 쓸 수 있다**로 읽는 것 | 사용 기록은 "무엇이 이미 쓰였나" 만 말한다. 발동 가능 판정은 `legal_actions` 의 일이다 |
| 카드 텍스트를 읽어 **방해 수·후속 전개**를 세는 것 | 엔진이 실행한 것만 적는다 |
| **"행동 수가 적으니 센 전개"** | 걸음 수는 길이이고 강함이 아니다 |

🔴 **주고받는 차이는 양쪽을 그대로 적는다**(한쪽은 패가 남고 다른 쪽은
묘지가 쌓이는 식). 🔴 **자동 순위도 승자도 없다.** 금칙어 부재를 시험이
고정한다(`test_e02`).

## 5. 실측

아래 수치는 **이번 구현에서 실제로 돌려 얻은 것**이다. 이전 단계의 수치를
옮겨 적은 칸은 없다.

### 5.1 실제 카드 입력 — 『성장』 입력

입력은 기존 입력과 같다(레시피와 시작 패). 🔴 **적어 둔 전개 경로
(`ORCUST_GIRSU_LINE` 의 수순)를 호출하지 않았다** — 그 상수에서 가져온 것은
**입력**뿐이다.

예산 `max_depth=6, max_nodes=400, max_results=3`.

| | 값 |
|---|---|
| 종료 | `budget_exceeded` (`max_results=3`) |
| 모은 결과 | **3개** (검증 3 · 재생 실패 0 · 재생 못 함 0) |
| 같은 결과에 닿아 합친 경로 | 0개 |
| 펼친 노드 / 최대 깊이 | 21개 / 5 |
| 탐색 소요 | **36.9초** |
| 재생 소요 | **28.5초** (🔴 탐색과 따로 적는다) |
| 범위를 끝까지 펼쳤는가 | **아니오** (결과 수 상한) |

| 항목 | 결과 1 | 결과 2 | 결과 3 |
|------|--------|--------|--------|
| 행동 | 4걸음 (선택 2회) | 5걸음 (선택 2회) | 6걸음 (선택 2회) |
| 경로 | 일반 소환 → 효과 → 효과 → 링크 소환 | …→ 링크 소환 → 링크 소환 | …→ 링크 소환 → 마·함 세트 → 링크 소환 |
| 남은 패 | 3장: 클리막스 · 열쇠 · 자각 | 3장: 클리막스 · 열쇠 · 자각 | **2장**: 열쇠 · 자각 |
| 자신 필드 | 갈라테아 `[30741503]` 앞면 | 갈라테아 | 갈라테아 |
| 자신 마·함 존 | 없음 | 없음 | **클리막스 뒷면 1장** |
| 자신 묘지 | 3장: 『성장』×2 · 기르수 | **4장**: 『성장』×2 · 기르수 · **갈라테아i** | 4장 (결과 2 와 같다) |
| 남은 엑스트라 | 5장 | **4장** | 4장 |
| 상대 필드 | 없음 | 없음 | 없음 |
| 일반 소환권 | 썼다 | 썼다 | 썼다 |
| 기록된 소환 사용 | 갈라테아 link ×1 | **갈라테아i link ×1** 추가 | 결과 2 와 같다 |
| 재생 검증 | ✔ | ✔ | ✔ |

**차이 문장**(보고가 실제로 내놓는 것, 요약):

- 결과 1 대비 결과 2 — 행동이 4걸음 → 5걸음(🔴 적은 쪽이 센 전개라는 뜻이
  아니다). 묘지가 다르다(갈라테아i 가 더 있다). 남은 엑스트라가 1장 적다.
  기록된 소환 사용에 `[48835607] link` 가 더 있다.
- 결과 1 대비 결과 3 — 위에 더해 패가 1장 적고(클리막스를 세트했다) 자신
  마법함정 존에 뒷면 1장이 있다.

🔴 **어느 쪽이 더 좋은지 고르지 않았다.** 결과 1 은 엑스트라 덱과 패를
아끼고, 결과 2·3 은 묘지에 갈라테아i 를 더 놓는다 — 그 둘 중 무엇이 나은지는
평가의 문제이고 이번 단계에 평가는 없다.

### 5.2 실제 카드 입력 — 토큰 입력 (패에 『성장』 이 없다)

예산 `max_depth=8, max_nodes=600, max_seconds=600, max_results=3`.

| | 값 |
|---|---|
| 종료 | `budget_exceeded` (`max_depth=8` · `max_results=3`) |
| 모은 결과 | **3개** (검증 3) |
| 펼친 노드 / 최대 깊이 | 96개 / 8 |
| 탐색 / 재생 소요 | **171.5초 / 34.9초** |

| 항목 | 결과 1 | 결과 2 | 결과 3 |
|------|--------|--------|--------|
| 행동 | 5걸음 (선택 1회) | 6걸음 | 7걸음 |
| 경로 끝 | 링크 소환 | 세트 → 링크 소환 | 세트 → 세트 → 링크 소환 |
| 남은 패 | 4장 | 3장 | **2장** |
| 자신 묘지 | 3장: 『성장』 · 갈라테아i · 기르수 | 같다 | 같다 |
| **상대 필드** | 토큰 `[46647145]` 1장 | 같다 | 같다 |
| 기록된 효과 사용 | 기르수 `e[2]` ×1 | 같다 | 같다 |
| 재생 검증 | ✔ | ✔ | ✔ |

🔴 상대 필드의 토큰은 기르수 ③ 이 양쪽에 1장씩 놓은 것이다. **그 칸이 상대에게
이득인지 손해인지는 이 단계에서 세지 않는다.**

🔴 이 입력의 세 결과는 **세트 장수만** 다르다. §2.4 의 잔여 중복이 실제로
드러난 자리이고, "서로 다른 좋은 전개 세 가지" 가 아니다.

## 6. 미지원과 한계

1. 🔴 **돌려준 결과가 가능한 모든 전개가 아니다.** 깊이 · 노드 · 시간 ·
   선택 분기 · 결과 수 상한이 모두 남은 길을 가리고, 지원하지 않아 후보가
   되지 못한 수와 확인하지 못한 선택 대안도 그렇다. 보고는 그 사실을
   `search_exhausted` 와 생략 줄로 적는다.
2. 🔴 **강약 평가가 아니다.** 순위도 점수도 승자도 없다.
3. 🔴 **상대의 선택은 탐색하지 않는다**(무방해는 명시적 정책이고 사실이
   아니다). 상대 자리에 고를 것이 남으면 그 노드에서 멈추고 그 사실을 적는다.
4. 🔴 **이번 턴만** 본다. `end_phase` 는 펼치지 않는다.
5. 🔴 **잔여 중복이 남는다**(§2.4). 상태가 다르면 따로 세므로 사람 눈에
   사실상 같은 전개가 둘로 남을 수 있다.
6. 🔴 **대표가 전체 최단 경로라는 보장이 없다**(§2.3).
7. 재생 시간 상한에 걸린 결과는 **검증되지 않은 것으로** 남는다 — 버리지도
   않고 검증된 비교에 섞지도 않는다.

## 8. 사용자 실행 진입점

### 8.1 CLI

```bash
python3 -m app.main combo \

  --search galatea \

  **탐색하지 않고** 그 사실을 적는다 — 🔴 조용히 깎아 주지 않는다(깎으면 그

```
/combo hand:… recipe:… search:galatea results:3

1. 검증된 서로 다른 결과 수(모은 수 · 재생 실패 · 재생 못 함과 함께)

   선택 생략 여부
5. 🔴 **아직 강약 평가가 아니라는 설명**

상세 첨부에 더 들어가는 것: 걸음마다의 행동 열쇠와 해결 중 선택 전부 · 모든
